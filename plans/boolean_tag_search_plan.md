# 布尔标签表达式搜索实施计划

## 文档状态

- 状态：等待实施
- 基线日期：2026-08-19
- 目标范围：高级标签搜索模式、精确标签表达式、表达式结果页、数据库表达式查询和相关测试
- 核心原则：复用 `boolean.py` 的语法解析能力；普通标签搜索和高级搜索彼此独立；优先复用现有结果页和工具栏结构

## 结论摘要

采用 `boolean.py` 解析高级标签表达式，不创建完整的自定义表达式解析器；仅为支持带特殊字符的标签增加最小引号字面量 tokenizer 适配。

对用户文档使用 `boolean.py` 已有的文字运算符：

```text
标签1 AND 标签2
标签1 OR 标签2
NOT 标签3
(标签1 OR 标签2) AND NOT 标签3
```

`boolean.py` 也支持符号运算符，但第一版只把 `AND`、`OR`、`NOT` 作为推荐写法，不重新定义其默认含义。高级表达式中的标签叶子节点使用严格相等匹配，不沿用普通标签搜索的子串匹配。

表达式解析结果只在高级搜索内部使用。解析树递归编译为现有数据库查询条件，每个标签条件使用关联关系的存在性语义，避免在 Python 中加载全部图片后做集合运算。

不修改数据库表结构、向量数据库和通用有限结果页；不实现表达式自动补全。

## 当前实现基线

当前搜索链路为：

```text
CustomSearchBox.searched
    -> MainWindow.on_search_triggered()
    -> services.search.open_search_results()
    -> 普通模式：StickerDBV1.search_stickers_by_tag() -> SearchResultPage
    -> 高级模式：StickerDBV1.search_stickers_by_tag_expression()
                 -> AdvancedSearchResultPage
```

当前主标签搜索位于 `src/stickerdb/v1/sticker_db.py`，行为是：

- 查询任意启用标签名称包含输入文本的图片；
- 使用 `DBTag.enabled == True`；
- 使用 `DBTag.name.contains()`，因此当前是子串匹配，不是严格相等匹配；
- 按 `modification_date`、`id` 倒序返回；
- 使用 `selectinload()` 加载结果图片的全部标签。

图片和标签通过 `tag_assoc` 多对多关联表连接，`DBStickerImage.tags` 和 `DBTag.stickers` 已经存在。`tag_assoc` 当前已有 `sticker_id`、`tag_id` 索引，第一版不增加数据库索引或迁移。

## 目标

- 在搜索类型下拉框中增加“高级”模式。
- 高级模式支持 `boolean.py` 的布尔表达式和括号嵌套。
- 普通“标签”模式保持单个文本查询的当前子串匹配行为，不解析表达式。
- 高级模式中的每个标签叶子节点只匹配名称完全相等的标签。
- 高级模式支持用双引号包裹包含括号、`&` 等表达式字符的标签名。
- 高级模式使用独立的 `AdvancedSearchResultPage` 结果页。
- 高级结果页标签标题固定为 `高级搜索[表达式]`，不把实际表达式写入标签标题。
- 高级结果页提供 `表达式`、`QLineEdit` 和 `提交` 控件，可以在当前结果页重新执行表达式并刷新结果。
- 保持只匹配启用标签的现有规则。
- `AND`、`OR`、`NOT` 和括号在数据库查询中保持正确逻辑。
- 负查询可以返回没有目标标签的图片，包括没有任何标签的图片。
- 查询结果保持当前排序和 DTO 导出行为。
- 表达式错误能够沿用主窗口已有的搜索失败提示路径。

## 非目标

- 不修改文本搜索和文件名搜索的语法；它们继续使用子串搜索。
- 不改变普通标签模式的子串匹配语义为严格相等匹配。
- 不实现标签别名、字段限定、范围条件、通配符或函数。
- 不实现任何表达式补全或表达式片段建议。
- 不引入 FTS5、Whoosh、向量检索或新的搜索索引。
- 不为表达式查询增加独立的持久化格式；搜索历史继续保存原始字符串。

## 语法和语义

### 推荐语法

```text
A AND B
A OR B
NOT C
(A OR B) AND NOT C
NOT (A OR B)
```

`boolean.py` 默认优先级为 `NOT > AND > OR`。括号优先级最高。表达式的含义完全交给库解析，不在项目中重新实现运算符优先级。

### 带特殊字符的标签

`boolean.py` 默认会把 `(`、`)` 识别为分组符，把 `&` 识别为 AND 运算符。因此标签名包含表达式字符时必须使用双引号：

```text
"角色(作品)" AND "动作&喜剧"
```

引号内的全部字符都属于标签文本，不参与表达式解析。引号内的双引号使用连续两个双引号表示，例如标签名 `他说"好"` 写为：

```text
"他说""好"""
```

这个能力只增加 `boolean.py` tokenizer 对引号标签字面量的识别，布尔运算符、优先级和表达式树仍完全使用 `boolean.py`，不重新实现完整表达式解析器。未加引号的特殊字符仍按表达式语法解释。

### 标签叶子节点

高级表达式中的每一个 `boolean.py` `Symbol` 都代表一个标签搜索文本：

```text
标签叶子 A
    -> DBTag.enabled IS TRUE
    -> DBTag.name == A
    -> 图片通过 tag_assoc 关联到该标签
```

因此高级查询 `A AND B` 表示图片至少存在一个名称恰好为 A 的启用标签，同时至少存在一个名称恰好为 B 的启用标签。由于采用两个独立的关系存在条件，同一个标签记录不会错误地同时承担两个叶子节点。

### 特殊情况

- 空查询继续返回空结果，不解释为“全部图片”。
- 正向未知标签没有匹配结果。
- `NOT` 未知标签按布尔逻辑返回全部图片，因为没有图片拥有该匹配标签。
- 禁用标签在正向和负向条件中都视为不可搜索，保持现有启用标签规则。
- `boolean.py` 的 `TRUE`、`FALSE`、`None`、`1`、`0` 等未加引号内容按常量处理并应拒绝；加引号后可以作为普通标签文本精确匹配。
- `AND`、`OR`、`NOT`、`TRUE`、`FALSE`、`None` 以及 `&`、`|`、`~` 等内容在未加引号时属于表达式语法或常量。标签名包含空格、括号、运算符、保留单词或数字常量时必须使用双引号。

## 实现方案

### 1. 增加直接依赖

在 `requirements.txt` 增加固定版本的 `boolean.py`，并在 `.venv` 中确认其支持当前 Python 版本、标准测试和 PyInstaller 打包路径。

包名为 `boolean.py`，导入名为 `boolean`。

### 2. 增加高级搜索模式

在 `src/services/search.py` 中增加 `SearchType.ADVANCED`，在 `src/ui/main_window.py` 的搜索类型下拉框中增加：

- 显示文字：`高级`；
- 存储值：`advanced`。

普通标签模式继续调用现有的 `search_stickers_by_tag()`。高级模式调用独立的
`search_stickers_by_tag_expression()`，避免普通标签查询意外获得表达式语义。

高级模式下，主搜索框仍用于首次输入表达式并打开高级结果页；搜索框只保留现有基础交互，不增加表达式补全。

高级模式的占位文字使用明确表达式语义的提示，例如 `搜索高级表达式...`，并关闭“未显式选择时提交第一条标签候选”的行为。

表达式解析错误从数据库搜索方法向上抛出一个清晰的查询错误，由现有 `MainWindow.on_search_triggered()` 统一显示。

### 3. 增加高级结果页

新增 `src/ui/page_advanced_search_result.py`：

- 定义 `AdvancedSearchResultPage`，继承 `FiniteStickerCollectionPage`；
- 初始构造时接收表达式、初始图片结果和一个重新查询回调；
- 在现有 `StickerListPage` 工具栏中加入 `QLabel("表达式")`、`QLineEdit` 和 `QPushButton("提交")`；
- `QLineEdit` 初始显示本次搜索表达式；
- 点击“提交”时调用重新查询回调，在当前页刷新图片模型，不新建标签页；
- 查询失败时在当前页显示错误提示，并保留原有结果；
- 标签页标题固定为 `高级搜索[表达式]`。

不新增独立 `.ui` 文件，优先通过现有工具栏扩展能力装配这三个控件。

`src/services/sticker_library_viewer_service.py` 增加高级结果页打开函数，负责创建页面、设置初始模型并打开标签页。重新查询回调由数据库表达式查询方法提供，避免结果页直接构造查询逻辑。

### 4. 在 `StickerDBV1` 内部解析和编译

在 `src/stickerdb/v1/sticker_db.py` 的标签搜索附近增加独立的
`search_stickers_by_tag_expression(expression: str)` 方法和最小数量的私有辅助逻辑：

1. 创建或复用一个 `boolean.BooleanAlgebra` 实例。
2. 使用最小 tokenizer 扩展识别双引号标签字面量，并将其转换为 `boolean.py` 可处理的 Symbol。
3. 解析非空查询文本。
4. 遍历 `Symbol`、`AND`、`OR`、`NOT` 节点。
5. 将 `Symbol` 编译成标签名称严格相等的关系存在条件。
6. 将布尔节点编译成现有 ORM 的 `and_()`、`or_()`、`not_()`。
7. 用编译得到的条件构建高级结果查询，并保留 `selectinload()` 和排序。

优先使用 `DBStickerImage.tags.any(...)` 表达关系存在条件；如果当前多对多关系不适合直接表达，则使用关联表的显式存在性条件。

表达式编译不需要额外的结果去重，因为每个叶子节点本身是存在性条件。这样也能避免多个标签条件共享同一个 JOIN 别名造成逻辑错误。

### 5. 保持普通查询兼容

普通“标签”模式继续使用当前 `contains()` 语义，不调用表达式解析器。高级模式使用严格相等标签叶子节点，并支持未加引号的普通 Symbol 和带双引号的标签字面量；表达式解析失败时应报告错误，而不是静默返回错误结果。

高级模式不实现标签候选、表达式片段或运算符补全。现有最近搜索历史行为是否显示不作为高级搜索功能的一部分。

## 验收标准

1. 用户可以从搜索类型下拉框选择“高级”。
2. 高级模式可以使用 `AND`、`OR`、`NOT` 和括号进行标签组合搜索。
3. 高级模式支持双引号标签字面量，括号和 `&` 等字符在引号内不会干扰表达式。
4. 高级模式中的标签叶子节点使用严格相等匹配。
5. 高级搜索结果使用 `AdvancedSearchResultPage`，并显示固定标题 `高级搜索[表达式]`。
6. 高级结果页提供表达式编辑框和提交按钮，提交后在当前页刷新结果。
7. 表达式优先级和括号行为由 `boolean.py` 解析结果决定，测试覆盖关键组合。
8. 标签条件在数据库查询中执行，不在 Python 端全量过滤图片。
9. 普通标签搜索保持现有子串匹配、启用标签过滤、排序和空查询行为。
10. 负查询、未知标签、无标签图片的结果符合已记录语义。
11. 文本和文件名搜索不受高级模式影响。
12. 高级模式不实现表达式补全。
13. 语法错误不会刷新原有结果，并能通过现有 UI 错误提示展示。
14. 定向测试和全量 `unittest` 测试通过。

## 已接受的权衡

- 高级表达式中的特殊字符标签需要使用双引号；普通标签模式仍保持原有文本查询方式。
- 普通标签模式继续使用子串匹配，高级模式使用严格相等匹配，两种模式的语义明确分离。
- 为兼容特殊字符，只增加引号标签的 tokenizer 适配，不扩展其他自定义语法。
- 高级搜索不提供表达式补全，用户直接输入或编辑完整表达式。
- 不引入完整搜索引擎或全文索引，换取更小的依赖和更低的数据维护成本。

实施时从阶段 0 开始，先确认 `boolean.py` 版本与项目 Python/打包环境兼容，再实现独立高级查询接口，随后接入“高级”搜索模式和 `AdvancedSearchResultPage`，不先扩展普通标签模式。
