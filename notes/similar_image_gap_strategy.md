# 相似图片查找：相似度落差截断策略

## 0. 模型切换说明

默认特征模型已切换为 `siglip_base_patch16_224`。下文中基于 DINOv2 的
相似度分布和默认阈值来自旧模型；SigLIP 切换后需要重新评估这些参数，
截断策略本身不依赖具体模型。

## 1. 背景

相似图片查找最初使用“固定相似度阈值 + 数量上限”的方式（例如 `>50%`
或 `>70%`）。实际使用中发现两个问题：

- 阈值调高时，很多相关图片查不到（相关结果可能落在 35%~50% 区间）。
- 阈值调低时，大量无关图片混进结果。

用 303 张图的 DINOv2 向量库分析后确认：全库两两余弦相似度中位数只有
约 0.048，每张图 top1 相似度中位数约 0.462；也就是说“相关”和“无关”
的分数区间天然重叠，任何单一固定阈值都无法同时解决漏检和误检。

因此改为观察每个查询自己的相似度排序曲线，用“最大落差”决定结果边界。

## 2. 策略概述

对每个查询：

1. 从向量库取回相似度最高的 200 个候选（数量上限可配）。
2. 按相似度降序计算相邻名次之间的分数差。
3. 如果存在明显落差（默认 ≥0.02），保留落差之前的结果，落差之后的
   候选视为另一个群体直接排除。
4. 如果曲线平缓（没有明显落差）：
   - 最高分很低（默认 <0.4）：判定没有可分的相似群体，返回空。
   - 最高分较高：保留整个高分平台，再按最低相似度过滤尾部。
5. 对保留结果应用最低绝对相似度过滤（默认 0.25）。
6. 如果只剩一个结果且分数不高（默认 <0.5），视为随机孤点，返回空。
7. 最终结果数不超过 100。

## 4. 参数说明

| 常量 | 默认值 | 作用 | 调参方向 |
| --- | --- | --- | --- |
| `SIMILAR_IMAGE_CANDIDATE_COUNT` | 200 | 一次取回的候选数量上限 | 图库很大时可以调大以保证不漏；查询慢时可以调小 |
| `SIMILAR_IMAGE_MAX_RESULTS` | 100 | 最终展示的结果数量上限 | 想展示更多结果就调大 |
| `SIMILAR_IMAGE_MIN_GAP` | 0.02 | 相邻排名之间多大的落差才算“明显分群” | 调大：更容易提前截断、结果更少；调小：更容易保留更多结果 |
| `SIMILAR_IMAGE_MIN_SIMILARITY` | 0.25 | 结果的最低绝对相似度 | 调大：过滤更多低分噪音；调小：可能找回低分相关结果 |
| `SIMILAR_IMAGE_LONE_RESULT_MIN_SIMILARITY` | 0.5 | 只有一个结果时要求的最低分数 | 调低：孤点结果更容易展示 |
| `SIMILAR_IMAGE_NO_GAP_MIN_TOP_SIMILARITY` | 0.4 | 曲线无落差时，最高分必须达到的值 | 调低：平缓曲线更容易返回结果；调高：更保守 |

## 5. 实际效果（2026-08-11，303 张 DINOv2 向量）

应用当前默认参数后的结果数量分布：

| 结果数 | 查询数 |
| --- | --- |
| 0 | 115（38%） |
| 1 | 57 |
| 2 | 38 |
| 3~5 | 44 |
| 6~20 | 20 |
| 21~100 | 29 |

典型例子：

- id 78：有大量明显重复，返回 28 张，相似度从 0.86 平滑下降到约 0.65。
- id 5：只有一个明显高分（0.556），只返回 1 张，不再拖出一串 0.4 左右的
  噪音。
- id 162：一整组高分图片分数挤在 0.48~0.54 且内部落差很小，保留整个
  高分平台（共 58 张）。
- id 1、id 22：分数曲线平缓且最高分刚过 0.4，分别返回 31 张和 34 张，
  属于“没有明显落差但整体偏高”的保留场景。
- 最高分只有 0.3 左右且曲线平缓的查询：返回空结果。

以上数字来自实现当天的真实库分析，图库内容变化后分布会随之改变，参数
可能需要重新评估。

## 6. 调参建议

- 觉得“结果太少 / 有些相关图没找到”：调低
  `SIMILAR_IMAGE_LONE_RESULT_MIN_SIMILARITY` 或
  `SIMILAR_IMAGE_NO_GAP_MIN_TOP_SIMILARITY`，也可以适当调低
  `SIMILAR_IMAGE_MIN_SIMILARITY`。
- 觉得“噪音太多 / 结果太杂”：调高 `SIMILAR_IMAGE_MIN_SIMILARITY`，
  或调高 `SIMILAR_IMAGE_MIN_GAP` 让截断更早发生。
- 图库规模变大后，如果担心高分平台很长，可以保持
  `SIMILAR_IMAGE_MAX_RESULTS` 不变或调低。

## 7. 注意事项

- `_select_similar_count()` 的输入必须是按相似度降序排列的分数列表，
  Chroma 的查询结果天然满足该顺序。
- 该策略只影响查询结果的截断，不影响向量库中存储的数据；模型切换
  （例如 ViT-B/16 与 DINOv2）后无需修改本策略，只需重新生成向量。
- 空结果仍会打开一个空标签页，目前没有单独的“未找到相似图片”提示；
  如果需要，可以在 UI 层补充。
