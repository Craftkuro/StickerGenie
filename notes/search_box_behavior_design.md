# 搜索框行为设计

## 1. 文档范围

本文档说明主窗口搜索区域当前的用户交互和实现约束，覆盖以下组件：

- `MainWindow` 中的搜索类型 ComboBox。
- `CustomSearchBox` 的输入框、搜索按钮和候选弹窗。
- `SearchSuggestionsProvider` 提供的最近搜索与标签候选。
- 搜索提交后的数据库查询和结果标签页。

本文档描述的是当前行为契约。后续修改搜索框时，应同步更新本文档和对应测试。

## 2. 搜索类型

主窗口提供两种搜索类型：

| 类型 | 候选内容 | 提交后的数据库查询 |
| --- | --- | --- |
| 标签 | 最近搜索、匹配的标签 | 图片关联的启用标签名称包含查询文本 |
| 文本 | 最近搜索 | `text_in_image` 包含查询文本 |

切换搜索类型时，MainWindow 会执行以下操作：

1. 更新输入框占位文字。
2. 设置回车键的默认候选提交策略。
3. 调用 `refresh_suggestions()`，按新类型重新获取候选。

标签模式启用“无显式选择时提交第一条候选”；文本模式关闭该策略。

## 3. 候选来源与排序

### 3.1 最近搜索

- 最近搜索在标签和文本模式中都会显示。
- 使用不区分大小写的 substring 匹配。
- 空查询可以显示最近的搜索记录。
- 记录按最近使用时间倒序排列。
- 重复搜索会移动到列表首位。
- 显示数量由 `recent_search_limit` 控制，配置为 `0` 时不显示。
- 内存和配置文件最多保存 100 条记录。

### 3.2 标签候选

- 只在标签模式且查询文本非空时提供。
- 使用数据库字面 substring 匹配；`%` 和 `_` 不作为 LIKE 通配符。
- 只返回启用的标签。
- 按 `Tag.order ASC, Tag.id ASC` 排序。
- 数量由 `tag_suggestion_limit` 控制，配置为 `0` 时不显示。
- 与最近搜索同名的标签候选会被去重，保留位置更靠前的最近搜索项。

候选列表整体顺序为：最近搜索在前，标签候选在后。因此标签模式的“第一条候选”可能是一条最近搜索。

## 4. 候选更新触发条件

候选请求只能由以下两种操作触发：

1. 用户编辑输入框，触发 `QLineEdit.textEdited`。
2. 调用公开方法 `CustomSearchBox.refresh_suggestions()`。

以下操作不会发起候选请求：

- 方向键、Page Up、Page Down、Home 或 End 改变候选高亮。
- QCompleter 自动设置当前行。
- 鼠标在候选上移动。
- 程序通过 `setText()` 更新输入框。
- 输入框获得焦点。
- 候选弹窗关闭或失去焦点。

用户编辑使用防抖请求，默认延迟为 300 毫秒。`refresh_suggestions()` 使用当前输入框文本立即请求，不经过防抖等待。

## 5. 输入文本与候选选择

搜索框将以下两个状态分开维护：

- **原始查询文本**：用户实际输入并用于生成当前候选的文本。
- **显式候选选择**：用户通过键盘导航选中的候选行。

候选高亮变化不得修改输入框文本。键盘导航时，组件会阻止 QCompleter 的默认文本预览行为，并保持原始查询文本和光标位置不变。

每次用户继续键入、刷新候选、应用一批新候选、关闭弹窗或按 Esc 时，显式候选选择都会被清除。

QCompleter 可能自动为第一行设置内部 current index。该状态不属于显式选择，组件在展示新候选后会清除自动 current index，使视觉状态和提交状态一致。

## 6. 键盘行为

### 6.1 导航键

候选弹窗可见时：

- Down：无选择时选择第一行，否则选择下一行。
- Up：无选择时选择最后一行，否则选择上一行。
- Page Down / Page Up：按弹窗当前可见行数翻页。
- Home / End：当按键由候选弹窗接收时，选择第一行或最后一行。

导航到首尾后继续按相同方向键不会循环，候选弹窗也不会改变输入框文本或重新查询候选。

### 6.2 回车键

回车提交规则如下：

| 当前状态 | 文本模式 | 标签模式 |
| --- | --- | --- |
| 有显式选择 | 提交选中的候选 | 提交选中的候选 |
| 无显式选择且有候选 | 提交输入框文本 | 提交第一条候选 |
| 没有候选 | 提交输入框文本 | 提交输入框文本 |

提交候选时，输入框会在提交发生时更新为候选的 `search_text`；如果候选未提供 `search_text`，则使用候选标题。该程序化文本更新不会重新请求候选。

只包含空白的文本不会触发搜索。

### 6.3 Esc

Esc 会执行以下操作：

- 清除显式候选选择。
- 关闭候选弹窗。
- 保留原始查询文本。
- 不触发搜索或候选请求。

## 7. 鼠标和搜索按钮

### 7.1 点击候选

鼠标点击候选会立即提交该候选，不需要再次按回车。输入框在提交时更新为候选搜索文本，并且只发射一次 `searched` 信号。

### 7.2 搜索按钮

搜索按钮始终提交输入框当前文本，不使用“标签模式默认第一候选”策略。即使候选弹窗中存在候选或显式高亮，点击按钮仍以输入框文本为准。

## 8. 弹窗与焦点

- 只有候选非空且输入框拥有焦点时才显示候选弹窗。
- 输入框获得焦点本身不会查询候选。
- 弹窗隐藏、窗口失活或输入框失去焦点时，显式选择被清除。
- 关闭弹窗不会改变原始查询文本。
- 用户继续键入时，旧的显式选择立即失效。

## 9. 异步候选一致性

每次候选请求都有单调递增的 request id，并记录对应查询文本。候选结果只有同时满足以下条件才会应用：

- request id 是当前最新请求。
- request id 大于最后一次已应用请求。
- 返回的查询文本等于最新查询文本。
- 返回的查询文本等于输入框当前文本。

提交搜索会停止防抖计时器并使所有在途候选请求失效，避免搜索后旧结果重新打开弹窗。

## 10. 搜索提交和结果展示

`CustomSearchBox` 只负责确定最终搜索文本并发射 `searched(str)`。MainWindow 在收到信号后读取当前搜索类型：

- 标签模式调用 `search_stickers_by_tag()`。
- 文本模式调用 `search_stickers_by_text()`。

搜索结果使用独立的 `SearchResultPage` 标签页展示，相似图片使用独立的 `SimilarImagesPage` 标签页展示。没有结果时仍打开空结果页，并在状态栏显示“未找到匹配图片”。

成功提交的搜索文本会加入共享的最近搜索历史。应用正常退出时，最近搜索按最新在前的顺序写入配置文件。

## 11. 行为不变量

实现和测试应始终保证以下条件：

1. 候选导航不会改变输入框文本。
2. 候选导航不会发起新的候选请求。
3. 只有显式选择才能覆盖文本模式的原始查询提交。
4. 标签模式的第一候选策略只影响回车，不影响搜索按钮。
5. 候选文本只在用户明确提交候选时写入输入框。
6. 新的用户输入会使旧候选选择和旧异步结果失效。
7. 一个提交动作最多发射一次 `searched` 信号。

## 12. 测试覆盖要求

`tests/test_custom_search_box.py` 应覆盖：

- 键入防抖和刷新请求。
- 获得焦点不请求候选。
- 过期结果被拒绝。
- 导航不改变文本或请求次数。
- 文本模式无选择时提交原文。
- 标签模式无选择时提交第一候选。
- 两种模式有显式选择时提交候选。
- 无候选时回退到原始文本。
- Esc、弹窗隐藏、鼠标点击和搜索按钮行为。
- 搜索提交使防抖与在途请求失效。

`tests/test_main_window_search_box.py` 应覆盖搜索类型切换时的默认候选提交策略。
